# Project 38: Requirement-to-Implementation Checklist

| Req # | Project Responsibility / Requirement Description | Target SQL Script / Object | Implementation Methodology | Verification & Audit Criteria | Status |
|:---:|:---|:---|:---|:---|:---:|
| **1** | Model users, products, impressions, clicks, carts, purchases, returns, and availability | `01_create_database.sql`, `02_create_tables.sql`, `03_constraints_and_indexes.sql` | 3NF normalized tables with InnoDB engine, primary & foreign keys, CHECK constraints, and indexes. | All 8 relational tables created with schema integrity validated via information_schema queries. | `COMPLETED` |
| **2** | Define positive, negative, and neutral behaviors with configurable weights | `06_feedback_scoring.sql`, `Feedback_Weighting_Policy.md` | `CASE` expressions mapping event types to numeric weights (`purchase` = +5, `cart`/`wishlist` = +3, `click` = +2, `view` = +1, `impression` = 0, `return` = -3). | Audited breakdown of positive, neutral, and negative interactions in `interaction_events`. | `COMPLETED` |
| **3** | Deduplicate repeated event ingestion without removing genuine repeated behavior | `05_event_deduplication.sql` | `ROW_NUMBER() OVER (PARTITION BY source_event_id ORDER BY ingestion_timestamp, event_id)` in CTE/staging table. | Distinguishes identical technical ingestions from authentic repeated user browsing events. | `COMPLETED` |
| **4** | Build user-item interaction summaries over configurable time windows | `07_user_item_interactions.sql` | Grouped aggregation on `(user_id, product_id)` with time filters `interaction_time >= @window_start AND <= @train_cutoff`. | Produces aggregated counts (views, clicks, carts, purchases) and cumulative implicit feedback score. | `COMPLETED` |
| **5** | Calculate product popularity by category and period | `08_product_popularity.sql` | `DENSE_RANK() OVER (PARTITION BY category, period ORDER BY popularity_score DESC)`. | Top-N product ranking generated per category with monthly/weekly granularities. | `COMPLETED` |
| **6** | Identify products with insufficient interaction history | `08_product_popularity.sql` | Conditional tagging (`CASE WHEN interaction_count < @cold_start_threshold THEN 'COLD_START' ELSE 'WARM' END`). | Flags low-history items to prevent cold-start distortion in collaborative filtering models. | `COMPLETED` |
| **7** | Distinguish products purchased from products merely viewed | `07_user_item_interactions.sql`, `11_candidate_generation.sql` | Explicit behavioral categorization flags (`has_purchased`, `has_viewed_only`, `has_returned`, `cart_abandoned`). | Validates behavioral states; ensures viewed items are not misclassified as purchased. | `COMPLETED` |
| **8** | Create historical interaction snapshots using a defined recommendation cutoff | `10_historical_snapshots.sql` | Point-in-time temporal filtering where all feature calculations freeze at `@train_cutoff`. | Zero interactions with timestamp > `@train_cutoff` appear in training snapshots. | `COMPLETED` |
| **9** | Generate eligible candidate products using catalog and availability constraints | `11_candidate_generation.sql` | Cross-join user base with active products filtered by business eligibility and prior purchase exclusions. | Excludes discontinued products and previously purchased items based on policy. | `COMPLETED` |
| **10** | Prevent items unavailable at prediction time from entering candidate sets | `11_candidate_generation.sql` | Temporal point-in-time join on `product_availability` (`effective_from <= @train_cutoff AND (effective_to IS NULL OR effective_to > @train_cutoff)`). | Zero out-of-stock items at cutoff appear in the candidate pool. | `COMPLETED` |
| **11** | Build chronological training and test interactions | `13_temporal_train_test_split.sql` | Time-aware split: Training (`timestamp <= @train_cutoff`) vs. Test (`timestamp > @train_cutoff AND <= @eval_cutoff`). | Eliminates data leakage inherent in randomized splitting. | `COMPLETED` |
| **12** | Identify and prevent data leakage caused by future purchases appearing in historical features | `16_testing_and_validation.sql` | Automated SQL assertion test suite running temporal contradiction queries. | Leakage queries return 0 violation records. | `COMPLETED` |
| **13** | Prepare negative-sampling candidate tables under an explicitly documented policy | `12_negative_sampling.sql`, `Candidate_Sampling_Policy.md` | Deterministic pseudo-random ranking (`MD5(CONCAT(user_id, product_id, @seed))`) selecting $K$ unobserved items per user. | Controlled ratio of negative samples excluding observed positive interactions and held-out test items. | `COMPLETED` |
| **14** | Calculate baseline recommendation metric inputs (held-out relevant items, candidate-set sizes) | `14_evaluation_datasets.sql` | Joins candidate pools with test ground truth (`is_relevant = 1/0`) and computes candidate set sizes per user. | Direct input ready for evaluation metric scripts (Precision@K, Recall@K, NDCG@K). | `COMPLETED` |
| **15** | Export separate datasets for collaborative filtering, popularity baselines, and content-based modeling | `15_model_exports.sql` | Specialized views and CSV export queries for each recommendation paradigm. | Generates 3 clean, documented tabular dataset views ready for downstream model consumption. | `COMPLETED` |
